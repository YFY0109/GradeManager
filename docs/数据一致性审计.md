# 数据一致性审计（2026-11-28）

> 范围：`app/`（FastAPI + PostgreSQL 查询）与 `web/src/`（Vue 3 展示/录入）。
> 目标：检查成绩、排名、统计、导出、权限范围之间的口径与数据一致性。

## 1. 已修复（P0/P1）

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `overview` / `rankings` 使用 `subjects.full_score` 而非考试快照 | 修改学科默认满分后，历史考试的满分、优秀率、总分统计被改写 | 统一改用 `exam_subjects.full_score`（`overview.py`、`rankings.py`） |
| 2 | 总分排名/统计导出的“齐全”判断只看已有成绩行 | 学生缺整科成绩行（未录入）时仍被算作齐全，总分和排名错误 | `query_rank` 与 `stats_data` 改为 `count(*) = exam_subjects 数量 AND bool_and(score IS NOT NULL)`，并统一 JOIN `exam_subjects` |
| 3 | 成绩录入、导出中心、学生成绩、排名页的科目列取全局科目表 | 新增科目后旧考试凭空多列；部分缺行时整科列消失；周考出现未考科目 | 统一按 `GET /api/exams/{pid}` 的 `exam_subjects` 快照加载，并按用户科目范围过滤 |
| 4 | 角色权限为空时回退到硬编码默认权限 | 把系统角色权限全部关闭后，仍会获得代码里的默认权限 | `capabilities_for` 仅在没有角色记录时回退 |
| 5 | 统计导出使用硬编码 85/70/60/30 | 修改“统计口径”后，页面与导出结果不一致 | `stats_data` 读取 `stats_config` 阈值 |
| 6 | 排名/统计查询未排除 `students.status != 'active'` | 转出/停用学生仍进入排名和统计 | 排名、统计 SQL 统一增加 `st.status = 'active'` |
| 7 | `/stats` 与统计表导出对班级教师返回全年级统计 | 仅 `report_class` 权限的教师可导出全年级均分/三率 | 统计接口与统计导出要求 `can_report_grade` + `view_stats`；导出页隐藏“统计表” |
| 8 | 排名导出未校验 `rank` 门控 | 关闭排名后仍可通过导出获得排名表 | 导出 `grade_rank` / `class_rank` 分别校验 `can_rank_grade` / `can_rank_class`；单科排名校验 `view_subject` |
| 9 | 角色权限可保存 `rank=false + rank_grade/class=true` | 权限展示与实际能力不一致 | 前端父项关闭时子项置灰并清空；后端写入统一 `normalize_permissions` |
| 10 | `view_stats` 未真正限制学情总览 | 自定义角色可绕过“查看汇总指标” | `overview` 要求 `view_stats`；报告页无权限时隐藏“学情总览”tab |
| 11 | **P0** 班级报告的 `classes` 数组包含全部班级 | 班主任/只读用户可通过 API 看到其他班级人数、均分 | 班级视角无条件裁剪为当前班（不再依赖 `rank_grade`） |
| 12 | **P0** 完整成绩表导出未按 `view_total/rank/view_subject` 裁剪列 | 无总分/无排名权限的用户仍能导出总分、平均分、年级/班内名次、单科成绩 | 完整表要求 `report_grade`；列由 `build_columns(capabilities)` 按能力裁剪；前端完整表入口同步收紧 |
| 13 | **P0** `manage_users` / `manage_roles` 可自我提权 | 委托管理员可给自己加权限、创建 admin 用户、重置管理员密码 | 禁止修改自己的角色/权限/范围；非 admin 不能操作管理员或权限更高的用户；只能授予自己拥有的能力和范围；不能修改系统角色 |
| 14 | `report_grade` + 受限班级范围时年级统计不裁剪 | 自定义角色可看全年级汇总 | 仍按 `report_grade` 视为全年级权限，文档明确；如需受限年级统计需单独建模（见 P2） |
| 15 | 科目范围受限时总分只算可见科目，且无 `view_total` 仍返回班级总分 | 教师被单独授予 `view_total` 时总分/满分错误 | 总分/等级/分段始终基于考试全部 `exam_subjects`；无 `view_total` 时班级总分字段置空，页面隐藏总分列 |
| 16 | 排名导出“缺考名单”不识别缺失成绩行 | 未保存空值的缺考学生不会出现在缺考名单 | 缺考名单改为 `students × exam_subjects LEFT JOIN scores` 生成 |
| 17 | 导入脚本使用旧考试类型并覆盖历史快照 | 全新库导入失败；重跑会改默认满分、考试满分、学生班级 | `scripts/import_exam.py` 改为 `monthly`；科目/考试科目/班级均不再覆盖历史 |
| 18 | 角色列表、配置读取只要求登录 | 普通用户可读取角色矩阵和导出模板 | 角色列表要求 `manage_users` 或 `manage_roles`；配置读取要求 `manage_config`；配置写入补审计 |
| 19 | 统计等级配置空列表导致 500 | 保存空等级列表后打开学情总览崩溃 | `GradeLevel` 阈值限制 0–1，等级列表至少 1 项 |

## 2. 验证结果

- 回归核对：学生名单、成绩记录、总分排名、均分和总分满分未变化。
- 临时修改语文默认满分后，历史考试的满分和统计仍和修改前一致。
- `overview` 与 `/stats` 的优秀率/良好率在默认与修改阈值后均一致。
- 班主任：年级报告 403、统计接口/统计导出 403、年级排名导出 200、班级报告 200；班级报告 `classes` 仅 1 个班。
- 科任老师：班级报告仅所授科目；成绩录入/导出科目列同步裁剪；无总分/年排。
- 角色写入 `rank=false + rank_grade=true` 时，返回与列表均自动归零子项；登录后 `can_rank=false`。
- 委托管理员：自改权限 400；授予 admin 角色/额外能力/额外班级 403；修改系统角色/管理员账号 403。
- 完整表导出：`report_grade` 用户无 `rank_grade` 时无年级名次列；关闭 `view_total` 时无总分/平均分列；班主任/只读用户完整表 403。
- 缺考名单：仅 1 条成绩记录的学生被正确列为缺考 4 科。
- 停用学生、缺行学生不进入总分排名，参考名单与基准一致。

## 3. 未修复的次要风险（P2）

1. `view_subject` 尚未覆盖 `exams.students`（学生成绩原始接口）；`overview`、单科排名、排名导出、完整表列已覆盖。默认角色均开启 `view_subject`。
2. 统计表的分数段仍固定为 5 段（90/80/70/60），未跟随 `stats_config.segment_count`；页面分段图已使用配置值。
3. 系统角色 `admin` 的权限仍可被 admin 编辑；若移除 `manage_roles/manage_users` 可能锁死，需要直接改库恢复。建议后续增加“最后一个管理员保护”。
4. `report_grade` 与班级范围组合仍按全年级处理；若需要“受限年级统计”需新增范围模型。
5. `GET /api/auth/me` 的 `role_permissions` 为原始并集，未做 rank 规范化；实际能力 `capabilities` 已门控。
6. 学生班级归属没有考试快照：转班后旧考试的班级名次/班级统计会变化（P1，需要新增 `exam_students` 或班级历史表）。考试**名单**已改为按成绩行快照，未参加学生不进本次报告。
7. 统计/导出多查询未使用 REPEATABLE READ；并发录分时可能混合不同提交状态。
8. `users.must_change_password` 仅前端提示，后端未强制拦截其他接口；登出未递增 token_version。
