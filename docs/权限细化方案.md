# 权限细化方案（报告分级 + 指标权限）

> 2026-11-27 · 依据用户确认：角色=命名模板；rank 为总开关；班主任默认可看年排

## 1. 目标

- 报告分为 **年级报告** 与 **班级报告**
- 普通班主任默认只能看 **本班班级报告**（但可看本班学生的年排）
- 指标级权限：年级报告、班级报告、所有排名、年排、班排、总分、单科、汇总指标
- 权限层级：**rank 是排名总开关**；rank_grade / rank_class 是子权限；只开 rank 不开子项无效

## 3. 层级规则（用户确认）

```text
rank 是总开关：
  rank = false  →  rank_grade / rank_class 均无效（所有排名不可见）
  rank = true + rank_grade = false + rank_class = false  →  仍无效（无具体排名可看）
  rank = true + rank_grade = true   →  可看年排
  rank = true + rank_class = true   →  可看班排
  rank = true + 两者都开            →  可看所有排名
```

- `report_grade` 与 `report_class` 独立配置
- 总分/单科/汇总指标独立配置

## 5. 角色与用户（用户确认）

- **角色 = 命名的权限模板**：名称、代码、权限集合；可新建/编辑/删除（系统角色不可删）
- **用户可直接应用某个角色**（权限来自角色模板）
- **用户也可单独配置**（不引用任何角色，权限完全来自用户级覆盖）
- 解析顺序：角色模板 → 用户覆盖（单独配置时角色为空）

## 6. 后端改造

- `roles` 表：`code / name / permissions JSONB / is_system`
- `users.role` 允许为空（单独配置）
- `current_user` 附带角色权限；`capabilities_for` 做 rank 门控与派生
- 新增 `GET/POST/PATCH/DELETE /api/roles`（`manage_roles`）
- 接口裁剪：
  - overview 无 class_pid → `report_grade`；带 class_pid → `report_class` + 范围
  - 年级排名 → `rank && rank_grade`
  - 班级排名 → `rank && rank_class`
  - 学生成绩 → `report_class`；年级名次列 → `rank_grade`，班内名次列 → `rank_class`
  - 学情总览排名列 → `rank_grade`
  - 总分/单科/汇总 → `view_total` / `view_subject` / `view_stats`

## 7. 前端改造

- **角色管理**（新页面，`manage_roles`）：角色列表、新建/编辑（名称/代码/权限开关）、删除
- **用户管理**：选择「应用角色」或「单独配置」；单独配置时编辑能力开关
- **角色管理**：入口按钮位于用户管理页顶部，点击打开抽屉（不再单独占菜单/页面）；角色列表、新建/编辑（名称/代码/权限开关）、删除
- **报告页**：顶部「年级报告 / 班级报告」切换，`report_grade` 有权限才显示年级报告；两种报告共用「学情总览 / 学生成绩」两个 tab
- **学生成绩/排名**：年级报告展示全年级名单与年级名次；班级报告展示本班名单与班内名次；年排/班排列按 `rank_grade` / `rank_class` 显示
- 菜单：用户管理（manage_users）统一承载用户与角色配置

## 8. 验收

- head_teacher：本班班级报告；年排/班排可见；无年级报告入口
- teacher：所授科班级报告；班排；无总分/年排
- grade_leader：年级报告 + 年排 + 班排
- viewer：班级报告只读；班排；无年排
- 角色修改即时生效（用户 token_version 递增）
- rank 关闭时所有排名 403/隐藏
- 只开 rank 不开子项：排名不可见
- 单独配置用户（role 为空）：权限完全来自用户覆盖

## 10. 权限分类与门控补强（2026-11-28）

- 角色/用户权限编辑统一由 `web/src/permissions.ts` 提供：
  - `rank` 是 `rank_grade` / `rank_class` 的父项；父项关闭时子项置灰、不可勾选，关闭父项会自动清空子项。
  - 保存前后端都会执行 `normalize_permissions`，避免出现 `rank=false + 子项=true` 的无效组合。
- `view_stats` 真正生效：
  - `/api/exams/{pid}/overview` 要求 `view_stats`，否则 403。
  - 报告页无 `view_stats` 时隐藏「学情总览」tab，直接进入「学生成绩」。
  - 统计表导出同时要求 `can_report_grade` + `view_stats`，导出中心隐藏无权限的「统计表」。
- 排名导出补上门控：`grade_rank` 校验 `can_rank_grade`，`class_rank` 校验 `can_rank_class`，单科排名校验 `view_subject`。
- 管理权限防提权：
  - 不能修改自己的角色/权限/数据范围；
  - 非 admin 不能修改管理员或权限高于自己的用户；
  - 只能授予自己拥有的能力、角色权限和班级/科目范围；
  - 非 admin 不能修改系统角色。
- 验证：角色写入非法组合自动归零；班主任/科任老师接口状态码与前端显隐符合矩阵；委托管理员的自提权/越权分配全部被拒绝。
