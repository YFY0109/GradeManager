# 项目规划（评审版）

> 状态：关键决策已确认（2026-11-27 评审）。项目：GradeManager（单校成绩管理系统）

## 0. 决策记录（2026-11-27 评审确认）

| 决策项 | 结论 |
|---|---|
| 服务范围 | **单校、单个年级**，验证后再考虑扩展 |
| 数据库 | **PostgreSQL**（评估后复用服务器环境或新建实例） |
| 后端 | **Python + FastAPI** |
| 部署 | **云服务器**（Linux + 宝塔） |
| 数据 | 先用**第一次月考成绩**验证；期中数据完成后由用户提供导入 |

## 1. 目标与范围

面向高一全年级、单次考试（月考/期中）的成绩管理：

- 成绩录入（科任老师/班主任）
- 自动校验（总分 = 各科之和、缺考处理、范围校验）
- 排名（班级/年级/单科，并列规则统一）
- 统计（班级均分、优秀率/及格率/过差率、分数段）
- 导出（Excel/PDF）
- 历史考试数据积累与查询（先月考，再期中）

暂不包含：跨校管理、教务排课、学生画像等。

## 2. 用户与权限（草案）

| 角色 | 权限 |
|---|---|
| 管理员 | 系统配置、用户管理、全部数据 |
| 年级组长 | 全年级数据查看、复核 |
| 班主任 | 本班数据、录入确认 |
| 科任老师 | 本人所授科目录入 |
| 查询用户 | 只读（按范围） |

- 所有成绩变更留痕：谁、何时、原值、新值（审计日志）。

## 3. 核心流程

考试创建 → 分配教师与科目 → 成绩录入（在线表格 / Excel 导入）→ 校验 → 排名统计 → 发布/导出 → 归档

## 4. 数据模型（草案）

- `students`：学号、姓名、班级、状态
- `classes`：名称、年级、班主任
- `subjects`：名称、满分
- `exams`：名称、日期、类型、状态
- `exam_subjects`：考试 × 科目、任课教师、满分
- `scores`：考试 × 学生 × 科目、分数、缺考标记、录入人、更新时间
- `audit_logs`：操作轨迹

关键约束：

- 同一学生同一考试同一科目唯一
- 分数范围 0..满分；缺考 = 无分（可空），不按 0 参与排名/统计
- 排名用 SQL 窗口函数：`RANK() OVER (PARTITION BY 班级 ORDER BY 总分 DESC)`

## 5. 技术方案（已确认）

| 项 | 选型 | 说明 |
|---|---|---|
| 数据库 | PostgreSQL | 复用服务器现有环境；需确认现有用途与隔离建库方案 |
| 后端 | Python + FastAPI | 配 SQLAlchemy + Alembic（迁移） |
| 前端 | 简单 Web（服务端模板或轻量 SPA） | MVP 阶段以录入与排名为主，细节 M2 前定 |
| 部署 | 云服务器（Linux + 宝塔） | 需要：HTTPS、登录鉴权、数据库访问隔离、备份策略 |
| Excel 交互 | xlsx-tools / openpyxl | 复用现有工具链；用于导入与对照校验 |

## 6. 数据迁移

- 数据源（第一次月考）：校方提供的月考 Excel，保存在受控环境。
- 后续数据源（期中）：由用户提供后补充
- 步骤：解析工作簿 → 建立学生/班级/考试 → 导入成绩（含缺考标记）→ 与 Excel 对照校验（总分、排名、平均分）→ 冻结归档
