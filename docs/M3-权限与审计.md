## 3. 数据范围

```sql
user_classes(user_id, class_id)     -- 可访问班级
user_subjects(user_id, subject_id)  -- 可访问/录入科目
```

- `admin` / `grade_leader`：不受限
- `head_teacher`：`user_classes` 内全部科目
- `teacher`：`user_classes × user_subjects`
- `viewer`：`user_classes` 只读
- 越权统一 **403**；资源不存在 **404**；不返回范围外数据

接口过滤点：

| 接口 | 过滤方式 |
|---|---|
| `GET /api/classes` / `subjects` | 仅返回范围内班级/科目 |
| `GET /api/exams/{id}/students` | 班级校验；teacher 的 `scores` 仅含所授科目 |
| `POST /api/exams/{id}/scores` | 逐条校验学生班级 + 科目 |
| 排名接口 | 年级结果按 `class_ids` 裁剪；单科校验科目 |
| `GET /api/exams/{id}/stats` | 班级裁剪；teacher 隐藏总分、仅保留所授科目 |
| 导出 | 完整表仅含授权班级；teacher 禁止完整表、仅可导出单科 |
| 配置/用户/审计 | 能力校验（403） |

> 导出裁剪时排名仍按**全量数据**计算（班主任看到的仍是学生的真实年级名次），仅裁剪输出行。

## 4. 审计日志

### 4.1 事件

| action | 触发 |
|---|---|
| `score.create` / `score.update` | 成绩首次录入 / 修改（记录旧值、新值、考试/学生/科目） |
| `exam.create` | 创建考试 |
| `config.update` | （预留）导出模板修改 |
| `user.create` / `user.update` / `user.disable` / `user.change_password` | 用户管理 |
| `auth.login.success` / `auth.login.failed` | 登录成功/失败（含原因与 IP） |
| `export.download` | 导出文件（kind/scope/参数） |

- 成绩仅在值变化时记录；一次批量保存只记实际变更
- 登录失败审计与失败计数**独立提交**，不随 401 回滚

### 4.2 查询

```text
GET /api/audit-logs?action=&actor=&table_name=&date_from=&date_to=&limit=&offset=
GET /api/audit-logs/scores?exam_pid=&student_pid=&limit=&offset=
```

- 仅 `view_audit` 能力（默认 admin / grade_leader）
- 分页默认 100、最大 500

## 5. 认证与登录加固

- JWT 载荷：`sub / uid / role / ver / iat / exp`
- 每个请求实时校验：账号 `status='active'`、`token_version` 一致（禁用/改密/权限变更立即失效）
- 连续 5 次密码错误锁定 15 分钟；成功登录清零
- 统一错误提示“用户名或密码错误”，不泄露账号是否存在
- 密码至少 8 位；改密后旧 token 立即失效
- 登录接口失败计数与审计独立提交

## 6. API 变更

### 新增

```text
POST   /api/auth/change-password      修改自己的密码
GET    /api/auth/me                   返回账号 + capabilities + scope
GET    /api/users                     用户列表（manage_users）
POST   /api/users                     创建用户
PATCH  /api/users/{user_pid}          更新角色/范围/状态/密码/能力
DELETE /api/users/{user_pid}          禁用用户（软删除）
GET    /api/audit-logs                审计查询
GET    /api/audit-logs/scores         成绩变更历史
```

### 变更

- `POST /api/auth/login`：增加锁定校验、失败审计、`must_change_password` 返回
- 所有业务接口：增加能力/范围校验（见第 3 节）
- `GET /api/auth/me`：新增 `capabilities` 与 `scope`

### 数据库（`db/003_m3_auth.sql`）

- `users`：`public_id / display_name / status / permissions / token_version / failed_attempts / locked_until / last_login_at / must_change_password`
- 新表：`user_classes`、`user_subjects`
- `audit_logs`：`created_at`、`actor`、`action` 索引

## 9. 已知边界

- 用户删除为软删除（`status=disabled`），不物理删除，便于审计追溯
- IP 级登录限流未在应用内实现（失败锁定已生效），计划 M4 由 Nginx `limit_req` 完成
- 审计日志未做归档/分区；数据量增长后可加定期归档
- `must_change_password` 目前仅登录响应返回标志，未在服务端强制拦截其他接口（客户端应引导改密）
- 单用户的能力覆盖通过 `permissions` JSONB 实现，暂无独立管理界面（客户端后续）
