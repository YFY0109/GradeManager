## 1. 部署前检查

| 项 | 检查内容 |
|---|---|
| 系统 | 检查操作系统与运行时兼容性 |
| 内存和磁盘 | 确认可用资源满足服务、日志及备份需求 |
| Nginx | 检查反代、HTTPS 站点与已有站点的端口配置 |
| PostgreSQL | 核对数据库版本、监听地址和访问范围 |
| Python | 项目要求 ≥3.12，使用 uv 安装独立运行时 |
| 代码拉取 | 确认 Git 和仓库连接可用 |
| 域名和证书 | 核对 DNS 解析、证书覆盖范围及续期配置 |
| 防火墙 | 核对对外入口及数据库访问限制 |

## 2. 目标架构

```text
Internet
   │  HTTPS (443)
   ▼
Nginx（宝塔，grade.example.com，站点证书）
   │  proxy_pass 127.0.0.1:8000
   ▼
uvicorn（systemd 托管，单 worker，仅监听 127.0.0.1:8000）
   │
   ▼
PostgreSQL 18.6（127.0.0.1:5432，仅本机）
```

- 应用进程：**systemd**（`grademanager.service`），非 root 专用用户，开机自启、崩溃重启
- 示例代码目录：`/path/to/GradeManager`
- Python：uv 安装独立 3.12 + 项目 `.venv`（不改系统 Python）
- 环境变量：`.env` 权限 600，DSN 指向本机 5432（无 SSH 隧道）

## 3. 部署方案

### 3.1 运行时

| 项 | 方案 |
|---|---|
| uv | 官方安装脚本（GitHub 可达），安装后 `uv python install 3.12` |
| 依赖 | `uv sync --frozen`（uv.lock 锁定） |
| 启动 | `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --limit-concurrency 8` |
| 时区 | `Asia/Shanghai`（systemd 环境变量 + PG 连接时区） |
| 日志 | journald（`journalctl -u grademanager`），限制日志大小 |

### 3.2 代码部署

**公共仓库 `YFY0109/GradeManager`（敏感数据分离）**

- 仓库只包含代码、文档模板与迁移脚本
- 本地开发配置、`reports/`、`local/` 和 `.env` 不提交到仓库
- 服务器直接 `git clone`（无需 deploy key）
- 更新：`git pull` → `uv sync --frozen` → 执行新增 SQL 迁移 → `systemctl restart grademanager`
- 敏感数据（账号密码、个人配置）保存在服务器 `.env` 与本地 `local/`，不公开

### 3.3 Nginx 站点

- 新建站点，例如 `grade.example.com`（宝塔或手写 conf）
- 反代 `http://127.0.0.1:8000`
- 部署覆盖站点域名的证书。
- HTTP → HTTPS 强制；HSTS
- `client_max_body_size 8m`（批量录入 JSON）
- `proxy_read_timeout 60s`（导出）
- 登录接口限流：`limit_req zone=gm_login burst=5 nodelay`（如 10r/m）
- 健康检查 `/health` 不鉴权

### 3.4 数据库

- 数据库/schema 已在服务器（M1-M3 通过本地隧道执行，数据已在 18.6 实例）
- 认证：为 `grademanager` 角色设置密码，`pg_hba.conf` 使用 `scram-sha-256`（127.0.0.1）
- 应用 `.env` 使用密码 DSN；不再依赖 trust
- 连接池：psycopg 每请求短连接（当前实现），单机低并发可接受

### 3.5 备份

- 定期执行 `pg_dump -Fc grademanager`，保存到专用备份目录。
- 保留 14 天；文件名含日期
- 备份后校验（`pg_restore --list`）
- 恢复演练：恢复到临时库，核对学生名单和成绩记录数。
- 可选：同步到 Cloudreve / 对象存储（后续）

### 3.6 安全

- uvicorn 仅 127.0.0.1；8000 不对公网开放
- PG 仅 127.0.0.1
- `.env` 600，运行用户非 root
- 登录失败锁定（M3 已实现）+ Nginx 限流
- 安全响应头（HSTS / X-Content-Type-Options / X-Frame-Options）
- 部署后禁用/改密测试账号；admin 密码按用户要求重置

## 4. 实施步骤

1. **服务器准备**：安装 uv → Python 3.12 → 创建运行用户与目录
2. **代码部署**：建私有仓库 → 推送 → 服务器 clone（deploy key）
3. **配置**：`.env`（DSN 密码、JWT secret、时区）
4. **依赖**：`uv sync --frozen`
5. **数据库认证**：设置角色密码 + pg_hba（先备份配置）
6. **systemd**：服务文件、开机自启、启动验证
7. **Nginx**：站点、证书、反代、限流、HTTPS
8. **备份**：脚本 + cron + 首次恢复演练
9. **验收**：公网访问、权限矩阵、导出、重启自恢复、性能与内存
10. **文档**：`docs/M4-部署.md`（含回滚方案）

## 5. 验收标准

| 项 | 标准 |
|---|---|
| HTTPS | 站点 `/health` 返回 `{"status":"ok"}`，证书有效 |
| API 文档 | `/docs` 可访问 |
| 登录 | admin 与 4 类测试账号可登录；错误 5 次锁定 |
| 数据 | 学生名单、成绩校验、排名和汇总统计与基准一致 |
| 导出 | 年级表及班级分表下载正常 |
| 权限 | teacher/head/viewer 在线上仍按 M3 矩阵生效 |
| 自启 | 重启服务器后服务自动恢复（systemd enabled） |
| 备份 | 每日备份生成、`pg_restore --list` 可读；恢复演练通过 |
| 安全 | 8000/5432 公网不可达；HTTP 强制跳 HTTPS |
| 内存 | 稳定运行后 `free -m` 可用内存 > 100MB；无 OOM |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 内存紧张 | OOM / 导出慢 | 单 worker、并发限制、导出串行；根据监测结果评估资源 |
| 宝塔 WAF 误拦截 API | 登录/导出失败 | 先启用观察；必要时该站点关闭 WAF 或加白名单 |
| 泛域名证书续期 | HTTPS 失效 | 现有 AllinSSL/宝塔续期任务；部署后确认续期覆盖 grade |
| 数据库认证切换 | 应用连不上 | 先备份 pg_hba，保留本地 psql 应急；分步验证 |
| 无 rsync、更新手工 | 发布慢 | GitHub + deploy key + `scripts/deploy.sh` 一键更新 |
| 磁盘空间不足 | 备份/日志占满 | 日志轮转；配置备份保留策略与监控 |

## 7. 回滚方案

- 代码：`git checkout <上一版本>` + `systemctl restart`
- 配置：`.env`、Nginx conf、pg_hba 均先备份（`.bak-YYYYMMDD`）
- 数据库：迁移均为幂等 `IF NOT EXISTS`；如需回滚，用备份恢复
- 服务：保留旧版本目录/分支，切换 systemd 指向
