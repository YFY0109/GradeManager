# M3 权限与审计规划（待确认）

> 2026-11-27 · 阶段目标：多角色、数据范围、审计日志、登录加固
> 前置：M2 后端 + 导出阶段已完成（现有 API 全部可用）

## 1. 目标

把当前“单管理员 + 全量数据”的后端升级为可给真实教师使用的权限系统：

- 5 类角色：管理员 / 年级组长 / 班主任 / 科任老师 / 只读
- 数据范围：按班级、科目授权，接口层强制过滤
- 审计日志：成绩修改前后值、操作人、时间；关键管理操作留痕
- 登录加固：失败锁定、token 失效机制、密码策略

## 2. 角色与能力

### 2.1 角色定义

| 角色 | 代码 | 定位 |
|---|---|---|
| 管理员 | `admin` | 全部数据、用户管理、配置管理 |
| 年级组长 | `grade_leader` | 全年级查看/统计/导出/审计；默认不改成绩 |
| 班主任 | `head_teacher` | 本班全部科目查看/排名/统计/导出；可录入本班成绩 |
| 科任老师 | `teacher` | 所授班级 × 所授科目的录入、查看、单科统计 |
| 只读 | `viewer` | 授权范围内只读（无写操作） |

### 2.2 能力矩阵（默认值）

| 能力 | admin | grade_leader | head_teacher | teacher | viewer |
|---|---|---|---|---|---|
| 查看范围 | 全部 | 全年级 | 本班 | 所授班 × 所授科 | 授权班 |
| 录入/修改成绩 | ✅ | ❌ | ✅（本班） | ✅（本科） | ❌ |
| 查看总分/总分排名 | ✅ | ✅ | ✅ | ❌（可配置） | ✅ |
| 导出 | ✅ | ✅ | ✅（本班） | ✅（单科） | ✅（授权范围） |
| 查看审计 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 用户管理 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 导出模板配置 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 创建/编辑考试 | ✅ | ❌ | ❌ | ❌ | ❌ |

### 2.3 能力覆盖（permissions JSONB）

默认能力由角色决定；管理员可对单个用户覆盖，例如：

```jsonc
{
  "can_enter_scores": true,
  "can_view_total": false,
  "can_export": true,
  "can_view_audit": false
}
```

未填写的键使用角色默认值。这样不引入“自定义角色”复杂度，又能处理特殊情况。

## 3. 数据范围授权

两张关联表：

```sql
user_classes(user_id, class_id)    -- 可访问的班级
user_subjects(user_id, subject_id) -- 可录入/查看的科目
```

规则：

- `admin` / `grade_leader`：忽略范围表，全量
- `head_teacher`：`user_classes` 内的班级，全部科目
- `teacher`：`user_classes × user_subjects` 的交集（两个都为空 = 无数据权限）
- `viewer`：`user_classes`（为空 = 无数据；如需全年级只读，授予全部班级）
- 科任老师跨班任教：同一科目可挂多个班级，直接多行记录

## 5. 审计日志

复用现有 `audit_logs` 表（`actor / action / table_name / record_id / old_value / new_value / created_at`）。

### 5.1 记录事件

| action | 触发 | 内容 |
|---|---|---|
| `score.update` | 批量保存成绩，值发生变化时逐条记录 | 考试/学生/科目、旧分、新分 |
| `score.create` | 首次录入 | 新分 |
| `exam.create` | 创建考试 | 名称、类型、科目 |
| `config.update` | 修改导出模板 | 旧配置摘要、新配置摘要 |
| `user.create` / `user.update` / `user.disable` | 用户管理 | 角色/范围/状态变化 |
| `auth.login.success` / `auth.login.failed` | 登录 | 用户名、IP（失败含原因） |
| `export.download` | 导出文件 | kind/scope/参数（不存文件内容） |

- 成绩审计按“旧值 ≠ 新值”记录；一次批量保存只记录实际变化
- `actor` 存 username；`record_id` 存业务标识（如 `exam=1;student=3;subject=1`）
- 索引：`created_at DESC`、`actor`、`action`

### 5.2 查询接口

```text
GET /api/audit-logs?action=&actor=&date_from=&date_to=&limit=&offset=
GET /api/audit-logs/scores?exam_pid=&student_pid=
```

- 仅 admin / grade_leader（可配置）
- 分页，默认 100 条，最大 500

## 6. 登录加固

| 项 | 方案 |
|---|---|
| 失败锁定 | 连续 5 次密码错误 → 锁定 15 分钟（`failed_attempts` + `locked_until`）；成功登录清零 |
| 错误提示 | 统一“用户名或密码错误”，不泄露账号是否存在 |
| Token 失效 | `users.token_version`；禁用用户/修改密码/重置密码时 +1，旧 token 立即失效 |
| 会话校验 | 每个请求校验用户状态与 token_version（单机小系统，一次索引查询可接受） |
| 密码策略 | 至少 8 位；管理员创建/重置；可选首次登录强制改密（`must_change_password`） |
| 登录限流 | M4 由 Nginx `limit_req` 实现；应用内以失败锁定为主 |
| HTTPS | 部署阶段（M4）统一处理，本地开发不强制 |

## 7. 数据库变更（`db/003_m3_auth.sql`）

```sql
ALTER TABLE users
    ADD COLUMN IF NOT EXISTS display_name TEXT,
    ADD COLUMN IF NOT EXISTS status TEXT NOT NULL DEFAULT 'active'
        CHECK (status IN ('active', 'disabled')),
    ADD COLUMN IF NOT EXISTS permissions JSONB NOT NULL DEFAULT '{}'::jsonb,
    ADD COLUMN IF NOT EXISTS token_version INT NOT NULL DEFAULT 0,
    ADD COLUMN IF NOT EXISTS failed_attempts INT NOT NULL DEFAULT 0,
    ADD COLUMN IF NOT EXISTS locked_until TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS last_login_at TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS must_change_password BOOLEAN NOT NULL DEFAULT FALSE;

ALTER TABLE users DROP CONSTRAINT IF EXISTS users_role_check;
ALTER TABLE users ADD CONSTRAINT users_role_check
    CHECK (role IN ('admin', 'grade_leader', 'head_teacher', 'teacher', 'viewer'));

CREATE TABLE IF NOT EXISTS user_classes (
    user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    class_id INT NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    PRIMARY KEY (user_id, class_id)
);

CREATE TABLE IF NOT EXISTS user_subjects (
    user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    subject_id INT NOT NULL REFERENCES subjects(id) ON DELETE CASCADE,
    PRIMARY KEY (user_id, subject_id)
);

CREATE INDEX IF NOT EXISTS idx_audit_created ON audit_logs(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_audit_actor ON audit_logs(actor);
CREATE INDEX IF NOT EXISTS idx_audit_action ON audit_logs(action);
```

## 9. 开发顺序

1. **权限基础**：迁移、角色/能力模型、用户管理 API、认证加固
2. **数据范围**：classes/exams/students/scores/rankings/stats/export 逐路由接入
3. **审计**：写入（成绩/管理/登录/导出）+ 查询接口
4. **测试与文档**：多角色矩阵测试、回归 M2/导出、更新文档

## 10. 验收标准

- 创建 5 类角色账号，逐端点验证可见/可写范围与矩阵一致
- 越权：403；不存在资源：404；不泄露其他班级/科目数据
- 成绩修改产生审计记录（操作人、旧值、新值、时间），查询可分页筛选
- 连续 5 次密码错误锁定 15 分钟；锁定期间正确密码也拒绝
- 禁用用户或改密后，旧 token 立即失效（401）
- admin 回归：M2 排名/统计/保存、导出 9 Sheet 全部通过；数据 0 变化
- 文档：`docs/M3-权限与审计.md`（实现与验收）

## 11. 风险与边界

| 风险 | 对策 |
|---|---|
| 范围过滤漏接某路由导致越权 | 统一依赖 + 路由级测试矩阵（逐端点断言） |
| 每请求查 users 增加延迟 | 主键/唯一索引查询，单机可忽略 |
| 审计日志增长 | 先按时间索引；后续可归档/分区 |
| 进程内限流重启失效 | 可接受；M4 由 Nginx `limit_req` 兜底 |
| 导出裁剪复杂 | teacher 仅允许单科导出；完整表仅 admin/年级组长/班主任（本班） |

## 12. 决策记录（2026-11-27 确认）

| 问题 | 决策 |
|---|---|
| 科任老师可见范围 | **仅所授科目**（可对单个用户配置开启总分查看） |
| 班主任录入 | **可录入本班全部科目** |
| 年级组长 | **可修改成绩**（全年级，所有改动留审计） |
| 登录锁定 | 连续 5 次失败锁定 15 分钟，成功登录清零 |
| 教师账号 | 管理员逐个创建（本阶段不做批量导入） |
| 审计范围 | 成绩修改 + 考试创建 + 配置修改 + 用户变更 + 登录 + 导出 |
| 密码策略 | 至少 8 位；管理员创建/重置；支持首次登录强制改密 |
